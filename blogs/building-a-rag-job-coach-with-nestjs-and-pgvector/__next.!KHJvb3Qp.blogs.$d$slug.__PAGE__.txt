a:T1be3,<p>Every AI resume tool I tried had the same flaw: it wrote impressive bullets about work I had never done. For a job seeker that is worse than useless — it becomes a liability in the interview. So I gave <a href="https://hunt-kit.netlify.app/">HuntKit</a> one rule: <strong>no claim without a source.</strong></p>
<p>This post walks through how that rule is enforced, from ingest to the final answer.</p>
<h2 id="the-shape-of-the-system">The shape of the system</h2>
<p>HuntKit is a Turborepo monorepo with two apps:</p>
<ul>
<li>a <strong>NestJS API</strong> (auth, profile, jobs, analyze and admin modules) on Render</li>
<li>a <strong>Next.js dashboard</strong> on Netlify</li>
</ul>
<p>Everything lives in one PostgreSQL database with the <code>pgvector</code> extension, accessed through Prisma.</p>
<h2 id="1-ingest-chunk-and-embed-the-profile-once">1. Ingest: chunk and embed the profile once</h2>
<p>A resume and a few project write-ups are split into small, self-contained chunks. Each chunk is embedded with OpenAI's <code>text-embedding-3-small</code> (1536 dimensions) and stored next to its text.</p>
<div class="remark-highlight"><pre class="language-sql"><code class="language-sql"><span class="token keyword">CREATE</span> EXTENSION <span class="token keyword">IF</span> <span class="token operator">NOT</span> <span class="token keyword">EXISTS</span> vector<span class="token punctuation">;</span>

<span class="token keyword">CREATE</span> <span class="token keyword">TABLE</span> profile_chunks <span class="token punctuation">(</span>
  id                uuid <span class="token keyword">PRIMARY</span> <span class="token keyword">KEY</span> <span class="token keyword">DEFAULT</span> gen_random_uuid<span class="token punctuation">(</span><span class="token punctuation">)</span><span class="token punctuation">,</span>
  profile_source_id uuid <span class="token operator">NOT</span> <span class="token boolean">NULL</span><span class="token punctuation">,</span>
  user_id           uuid <span class="token operator">NOT</span> <span class="token boolean">NULL</span><span class="token punctuation">,</span>
  chunk_index       <span class="token keyword">int</span>  <span class="token operator">NOT</span> <span class="token boolean">NULL</span><span class="token punctuation">,</span>
  content           <span class="token keyword">text</span> <span class="token operator">NOT</span> <span class="token boolean">NULL</span><span class="token punctuation">,</span>
  embedding         vector<span class="token punctuation">(</span><span class="token number">1536</span><span class="token punctuation">)</span>
<span class="token punctuation">)</span><span class="token punctuation">;</span>
</code></pre></div>
<p>Embedding happens once per source, not on every analysis — that keeps each job analysis fast and cheap.</p>
<h2 id="2-retrieve-top-8-chunks-by-cosine-similarity">2. Retrieve: top 8 chunks by cosine similarity</h2>
<p>When a job description comes in, it is embedded the same way and compared against that user's chunks. The eight closest chunks become the <strong>only</strong> evidence the model is allowed to use.</p>
<div class="remark-highlight"><pre class="language-ts"><code class="language-ts"><span class="token keyword">const</span> results <span class="token operator">=</span> <span class="token keyword">await</span> <span class="token keyword">this</span><span class="token punctuation">.</span>prisma<span class="token punctuation">.</span>$queryRaw<span class="token operator">&#x3C;</span>RetrievedChunk<span class="token punctuation">[</span><span class="token punctuation">]</span><span class="token operator">></span><span class="token template-string"><span class="token template-punctuation string">`</span><span class="token string"></span>
<span class="token string">  SELECT c.id, c.content, ps.title AS source_title,</span>
<span class="token string">         1 - (c.embedding &#x3C;=> </span><span class="token interpolation"><span class="token interpolation-punctuation punctuation">${</span>vectorLiteral<span class="token interpolation-punctuation punctuation">}</span></span><span class="token string">::vector) AS score</span>
<span class="token string">  FROM profile_chunks c</span>
<span class="token string">  JOIN profile_sources ps ON ps.id = c.profile_source_id</span>
<span class="token string">  WHERE c.user_id = </span><span class="token interpolation"><span class="token interpolation-punctuation punctuation">${</span>userId<span class="token interpolation-punctuation punctuation">}</span></span><span class="token string">::uuid AND ps.status = 'ready'</span>
<span class="token string">  ORDER BY c.embedding &#x3C;=> </span><span class="token interpolation"><span class="token interpolation-punctuation punctuation">${</span>vectorLiteral<span class="token interpolation-punctuation punctuation">}</span></span><span class="token string">::vector</span>
<span class="token string">  LIMIT </span><span class="token interpolation"><span class="token interpolation-punctuation punctuation">${</span>limit<span class="token interpolation-punctuation punctuation">}</span></span><span class="token string"></span>
<span class="token string"></span><span class="token template-punctuation string">`</span></span><span class="token punctuation">;</span>
</code></pre></div>
<blockquote>
<p><strong>Why not a separate vector database?</strong> For an MVP, keeping vectors in the same Postgres as users and jobs means one backup, simple joins and one bill.</p>
</blockquote>
<h2 id="3-refuse-to-guess-when-there-is-no-evidence">3. Refuse to guess when there is no evidence</h2>
<p>If retrieval returns nothing — for example, the user has not added a profile yet — the API does not call the model at all. It records a <code>low_context</code> run and tells the user to add profile sources first. An honest "I don't know" beats a confident invention.</p>
<h2 id="4-generate-with-citations">4. Generate with citations</h2>
<p>Each retrieved chunk is passed to the model labelled with its id and source:</p>
<div class="remark-highlight"><pre class="language-text"><code class="language-text">[chunkId: 3f2c…] (source: Resume, score: 0.712)
Designed and shipped NestJS, TypeScript and PostgreSQL backend services…</code></pre></div>
<p>The model (<code>gpt-4o-mini</code>) returns structured JSON — match score, strengths, gaps, tailored bullets and likely interview questions — where strengths reference the <code>chunkId</code> they came from. The API returns those citations to the dashboard, so every suggestion can be traced back to a line of the user's real profile.</p>
<h2 id="5-log-every-ai-run">5. Log every AI run</h2>
<p>Every analysis writes a row to an <code>ai_runs</code> table: model, prompt and completion tokens, latency, status, and the ids of the retrieved chunks. When an answer looks wrong, I can see exactly what the model was given instead of guessing.</p>
<p>Try the <a href="https://hunt-kit.netlify.app/">live demo</a> or read the <a href="https://github.com/JaveedIshaq/job-huntkit-workspace">code on GitHub</a>.</p>
