# Week 7: Next.js Admin Foundation

## Objective

Stop being backend-only and start looking like a full-stack product engineer.

## Main Outcome

By the end of this week, you should have:

- a usable `Next.js` admin shell
- auth-connected dashboard
- plant and diagnosis management screens
- clear understanding of core Next.js patterns

## Build Tasks

- initialize `Next.js` app if not already done
- set up auth flow for admin users
- create dashboard layout
- create plant list page
- create diagnosis review page
- show diagnosis status and processing state
- add loading and error states

## Study Focus

- App Router
- server vs client components
- route handlers
- form submission patterns
- loading and error boundaries

## UI Focus

Do not obsess over design polish. Focus on:

- clean information hierarchy
- usable tables
- filters
- upload workflow
- obvious status states

## Interview Prep Focus

Prepare answers for:

- Why use Next.js for admin/product web?
- How do server and client boundaries affect architecture?
- How did you handle auth integration in the web app?

## End-Of-Week Deliverables

- working admin shell
- authenticated dashboard
- plant/diagnosis admin UI
- loading/error states
- notes on Next.js architecture choices

## Red Flags

- spending time on branding before workflows exist
- building React pages without understanding data boundaries
- no state for loading, failed, or empty results
