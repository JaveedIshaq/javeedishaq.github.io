# Week 5: AI Diagnosis Workflow

## Objective

Implement the first practical AI feature that actually improves the product.

## Main Outcome

By the end of this week, you should have:

- AI diagnosis pipeline
- structured diagnosis result storage
- care recommendation generation
- result history endpoint
- a real AI story for interviews

## Build Tasks

- implement diagnosis input pipeline from images and plant context
- store structured diagnosis result data and confidence metadata
- implement care recommendation generation flow
- add diagnosis/result history retrieval
- add AI-run logging
- add basic cost/latency tracking

## Study Focus

- structured outputs
- image/context-to-recommendation workflow
- confidence and uncertainty handling
- recommendation generation at a practical level
- why diagnosis history and result traceability matter in this product

## AI Product Focus

Understand the difference between:

- plant identification
- plant-health diagnosis
- care recommendation
- follow-up workflow automation

## Interview Prep Focus

Prepare answers for:

- How does the diagnosis pipeline work in your product?
- How do you structure AI results so they are usable in the app?
- Why is this more useful than a generic plant chatbot?
- How do you handle uncertainty or weak diagnosis confidence?

## End-Of-Week Deliverables

- working diagnosis pipeline
- stored structured diagnosis results
- recommendation flow
- AI-run log
- architecture notes for AI workflow

## Red Flags

- adding agent complexity before diagnosis works
- no trace of AI result history
- inability to explain the diagnosis workflow simply
