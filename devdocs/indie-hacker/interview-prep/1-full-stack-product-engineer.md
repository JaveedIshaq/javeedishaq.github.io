# Full-Stack Product Engineer Interview Prep

## Goal

Pass remote full-stack product-engineer interviews for roles centered on:

- Flutter for mobile
- React / Next.js for web and admin
- TypeScript / NestJS for backend
- PostgreSQL / Supabase for data and auth
- practical AI integration

## What Companies Actually Want

They do not primarily want:

- a framework collector
- a tutorial consumer
- a pure mobile developer claiming full-stack
- a generic AI enthusiast

They want someone who can:

- ship features end to end
- reason about tradeoffs
- work across frontend, backend, and database layers
- move fast without destroying reliability
- explain decisions clearly
- integrate AI into real workflows, not just demos

## Core Competencies You Must Be Able To Defend

### 1. Product Thinking

Be ready to explain:

- the user problem
- why the feature matters
- what you cut to ship
- what would be version 2

### 2. Full-Stack Delivery

You should be able to walk through:

- UI entry point
- API boundary
- validation
- business logic
- database operations
- auth and permissions
- background jobs
- failure states

### 3. System Design

Know how to explain:

- REST API structure
- auth and RBAC
- file uploads
- notifications
- queues
- caching
- observability
- rate limiting
- scaling decisions

### 4. Practical AI Integration

You should be able to explain:

- why the AI feature exists
- how inputs are prepared
- how outputs are validated
- when human review is needed
- how you control cost
- how you know it is useful

## The Minimum Interview Story Set

You need strong answers for:

1. Tell me about yourself.
2. Why Product Engineer instead of Flutter-only roles?
3. Why this stack?
4. Tell me about a system you designed.
5. Tell me about a feature you shipped end to end.
6. Tell me about a time requirements were messy.
7. Tell me about a performance or reliability problem.
8. How do you decide between Supabase and a custom backend?
9. How do you add AI to a product responsibly?
10. What did you build recently that proves your current direction?

## What To Build As Proof

Your flagship proof should show:

- mobile app in Flutter
- admin or web surface in Next.js
- backend in NestJS
- PostgreSQL or Supabase
- one practical AI feature

Recommended proof:

- `plantUSA rebuilt properly`

## Red Flags That Will Hurt You

- talking more about tools than outcomes
- saying you know NestJS deeply without recent proof
- overselling AI buzzwords
- showing only old Flutter-heavy work
- failing to explain auth, validation, and data flow clearly
- giving architecture answers with no tradeoffs

## Weekly Interview Routine

### 3x per week

- practice one backend explanation
- practice one frontend explanation
- practice one system-design prompt

### 2x per week

- do one mock “tell me about yourself”
- do one mock “design this system”

### Weekly

- refine one case study
- rewrite one weak bullet on your resume
- add one concrete number or outcome to your proof
