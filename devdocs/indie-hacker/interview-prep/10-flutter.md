# Flutter Interview Prep

## Your Goal

Flutter is your strongest edge.
Do not present it as your only edge.

You need to sound like:

- a product engineer with deep Flutter strength

not:

- a mobile-only candidate trying to stretch into full-stack

## What You Must Be Able To Explain

### UI And State

- widget tree basics
- rebuild behavior
- state boundaries
- BLoC / Riverpod reasoning
- form handling

### Architecture

- clean architecture principles
- repository pattern
- service boundaries
- offline-first thinking
- maintainability decisions

### Performance

- startup time
- image loading
- lazy loading
- rebuild reduction
- memory issues

### Data And Integration

- API integration
- auth flows
- local persistence
- realtime data
- sync behavior

### Shipping

- store release flow
- crash handling
- production debugging
- device-state edge cases

## Questions You Should Expect

- how do you structure a large Flutter app?
- BLoC vs Riverpod?
- how do you optimize performance?
- how do you handle offline and sync?
- how do you integrate backend APIs safely?

## What Good Answers Sound Like

`I use Flutter as a strong delivery layer, but I think about it in terms of product systems, not just screens. My focus is keeping state predictable, network boundaries clean, and UI responsive under real production conditions.`

## Practical Prep

- explain one production Flutter architecture
- explain one performance fix
- explain one backend-connected mobile workflow
- explain one offline or sync challenge

## Red Flags

- only talking about UI polish
- not connecting Flutter to backend/system concerns
- weak explanation of state boundaries
